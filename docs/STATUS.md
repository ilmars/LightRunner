## Known issues

- APC mini and Companion not yet tried on real hardware. For the APC: the older model's MIDI numbers come from community mappings, and the mk2's colour message follows Akai's protocol document but hasn't been tried on a real mk2. What to look for is in [companion.md](companion.md). OSC has only been tried against a simulated sender.
- Jump check: with another seed (`--seed 4` on stage L1) it finds a 5.5 % step in one frame when Blackout comes while a light is held: Blackout's 1 s fade and the hold's 1 s release run together (any colour; the default seeds pass). Not fixed yet.
- Frame timing: about one frame in a few minutes is up to 3.4 ms late (spec: ±3 ms). Not visible, but the spec's 1-hour timing test would fail on it.
- The stage view on the operator page keeps showing the last frame while the tablet is offline (the red banner does show).
- "Compare with a file" with the Lightkey project lists P5 as new and ticked; untick it (P5 is not used).
- One server test (show saved with backups) has failed once on Windows and passed on re-run.
- The server test "Save, add and Save as quick look work after Basic lights" failed once in a full run on Windows (21 Oct: EPERM renaming `show.json.tmp` to `show.json`, a file still held open) and passed on re-run.
- Each Save of an Any colour adds a hidden custom preset; old ones aren't cleaned up. The same goes for a changed effect (a hidden "Custom effect"), and for each edit made in Prepare to a colour or effect that is lit on stage (a hidden copy of it as it was, `<id>-kept`).
- "Compare with a file" lists the ready-made effects as removed when the file has none of them (they are not ticked; applying it would delete them).
- Effects haven't met the real rig yet: speeds, sizes and the 3-flashes-a-second limit are checked on the engine and in a browser, not in the dark room. Whether a bar needs Reversed is for the owner to check at the church.
- Prepare: Live (or running-order Edit) throws the draft away at once, without asking.
- Prepare: the draft's picture can run a frame or two apart from the real stage's.
- Prepare and the restyle haven't met the real iPad yet: the new colours, the violet top bar, the Live / Prepare switch and Go ▸ need a look in the dark room. So does Individual lights (changing many lights at once has only been tried on one computer).
- The restyled bottom bar fits 1080 px with up to six Flash buttons (All and five light groups), checked again in Inter with stage-l1 (21 Oct). With more groups the bar takes two lines by itself (Flash above Master and the buttons) and the stage area gets about 66 px less height; checked with eight light groups. The page checks again when Inter has loaded, as it arrives after the first paint.
- Individual lights, left as they are: a light's button pinned at the plan's edge can still be partly covered by a neighbour (the spreading moves only the smaller of the two); a colour tap on picked lights at different levels is one command per level, so they change a frame or so apart; a `manual` command that holds a segment and then its whole light with `releaseSegments` lets go of that segment again (API only, the page never sends it); a light in two groups held from elsewhere shows the first held group's colour.
- With 14 or more groups the bottom bar's Flash row is too long and has to be scrolled sideways, which is awkward by touch.
- The home-screen icon and the browser-tab icon haven't been seen on the real iPad yet.
- Not yet tried on a real phone: the phone remote was checked in a browser at phone sizes only.
- Not yet tried on the real iPad: finger drag in the running order, the on-screen keyboard over the quick-look sheet, two fingers on Flash, pointer capture on iOS Safari, the White, Amber and UV slider tints in the dark room.
- The stage view doesn't know what each fixture can do: amber shows orange on the colour-temperature front lights, which only go warmer. (UV is already left out where there is no UV.)
- **Before going back to a build from before effects, export the show** (Settings > Export show file), or keep `shows/stage-l1.json` to install it again: older builds can't read a show that has effects, and every show this version has run has some (the ready-made ones).
- Going back to a build from before white, amber and UV loses them: older builds can't read live colours like `live:key-lights:#ff0000:a100` when restoring the stage, and drop amber and UV from saved custom presets.
- A layout change in the middle of a White, Amber or UV slider drag rebuilds the sliders and drops the drag (rare: only when the show is edited at that moment).
- Restoring a backup from before a group was marked as a smoke machine brings that group back as a light (Basic lights and looks would drive it); mark it again in Patch. "Compare with a file" never changes whether a group is smoke.
- Smoke support has not met a real smoke or haze machine yet. Machines with a separate fan or mode channel need a fixture type whose level channel is "dimmer" (Patch warns when it isn't); other channels keep their fixed values.
- The server test "Add, rename, move and delete edit the running order" has failed once in a full run on Windows and passed on re-run. So has the APC test "Flash is held while the button is down" (21 Oct, with a browser and a server running beside it).
