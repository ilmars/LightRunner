# Effects Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Moving effects on Light Runner's light groups (colour fade, wave and repeating waves, chase, sparkle, breathe, meteor, fill, yo-yo) running across every segment of the bars, with a tempo per song and tap tempo, an editable effects list in the colour picker, and effects working with Save, Preview, quick looks and the phone.

**Architecture:**
- **Segments.** The engine learns segments first: each repeated set of colour channels in a fixture type is one segment. A group's segments, in group order (each fixture optionally reversed), form one line.
- **Effects.** An effect is a new preset layer kind (`kind: 'effect'`), rendered by pure functions of beat or second phase, segment position and settings.
- **Tempo.** A stage tempo (beats per minute) drives a beat clock. Each preset run keeps its own beat and second phase, so tempo changes never jump.
- **Editing.** Live effect tweaks are live presets (like Any colour) that Save turns into hidden presets. The effects list is edited like the colour list.

**Tech Stack:** Node 24 (type stripping), TypeScript (erasable syntax only), zod, node:test, plain HTML/JS/CSS (no build).

**Spec:** [docs/superpowers/specs/2026-10-19-effects-design.md](../specs/2026-10-19-effects-design.md). Read it all, including "My calls" and "Settled after the builder check". Background: docs/SPEC.md "Effects engine and transitions" and "Effect library and layers".

## Global Constraints

- Branch `effects` from `main`; work in the main checkout (no worktree). Don't push.
- The engine stays pure: no timers or I/O; effects are functions of phase, segment position and settings. Timing comes from the clock, never from frame counts.
- Phase advances by speed × elapsed time, so changing tempo or speed never makes an effect jump.
- Fades between anything keep the existing crossfade. `npm run jump-check` must pass; it judges transitions while effects run, not the effects' own motion (Task 4).
- Light safety: no segment's brightness may rise and fall by more than 20 % more than 3 times a second. Otherwise the engine halves that effect's rate (repeatedly). Colour changes at the same brightness don't count.
- Basic lights and Blackout are always still. Smoke groups never run effects.
- Every input is a `Command` through `App.command()`. The server is the single source of truth.
- TypeScript: erasable syntax only, `.ts` imports, `import type` for types.
- Web: design system tokens (`web/shared/theme.css`, docs/design-system.md), quiet controls, 44 px targets, nothing bright. UI text in plain English, sentence case.
- 40 fps with the whole rig running effects, within ±3 ms of 25 ms (`npm run timing-probe` on the church Mac; locally it just has to run).
- `npm test`, `npm run typecheck` and `npm run jump-check` pass before every commit.

- `LayerContext.index` is the segment's position in its group's line and `count` is the line's length. The line is the group's fixtures in group order, each fixture's segments in order, reversed when `fixture.reversed`.
- `OperatorLayout.fixtures[].segments: number`, plus `reversed: boolean`.

Rules:
- `FixtureRun` gets `cells: Light[]` (one per segment). `light` stays as the fixture's first segment, so the `lightOf` test helper keeps working.
- `GroupRun.out` becomes one Light per segment of the line.

**Interfaces — Produces:**

```ts
export const EffectKind = z.enum(['colourFade', 'wave', 'chase', 'sparkle', 'breathe', 'meteor', 'fill', 'yoyo']);
export const EffectSpeed = z.union([z.object({ beats: z.number().min(0.25).max(64) }), z.object({ seconds: z.number().min(0.25).max(600) })]);
export const EffectLayer = z.object({
  kind: z.literal('effect'),
  effect: EffectKind,
  colours: z.array(ColourSpec).min(1).max(6),
  speed: EffectSpeed,
  direction: z.enum(['ltr', 'rtl', 'centreOut', 'outsideIn']).default('ltr'),
  waves: z.number().int().min(1).max(16).default(1),
  size: unit.default(0.5),
  edge: z.enum(['soft', 'hard']).default('soft'),
  intensity: unit.default(1),
});
export const Layer = z.discriminatedUnion('kind', [StaticLayer, EffectLayer]);
export const isEffectPreset = (p: Preset): boolean => p.layers.some((l) => l.kind === 'effect');
```

- In `effects.ts`:
  - `export function renderEffect(out: Light, fx: CompiledEffect, ctx: LayerContext, cyclesPerSecond: number): Light`. `CompiledEffect` is the layer with its colours resolved to `Light`s once.
  - `export function safeRate(fx: CompiledEffect, cyclesPerSecond: number): number` returns the rate actually used. It halves the rate while one segment's brightness swings (≥ 20 % depth) exceed 3 per second.
  - Position `x` in 0..1 is `ctx.index / max(1, ctx.count − 1)`, mapped by `direction`:
    - `ltr` x
    - `rtl` 1 − x
    - `centreOut` |x − 0.5| × 2
    - `outsideIn` 1 − |x − 0.5| × 2
  - Phase is `ctx.beats / speed.beats`, or `ctx.time / speed.seconds`, scaled by `safeRate`.
  - Soft edges use smooth curves (cosine and smoothstep). Hard edges use steps.
- Effects:
  - **colourFade:** every segment the same; it moves through `colours` in order, one colour per cycle, crossfading (soft) or switching (hard).
  - **wave:** the phase moves along x with `waves` repeats.
    - With 1 colour, brightness rolls: soft = 0.5 + 0.5 cos; hard = on for `size` of each wave.
    - With 2 or more colours, the colours roll along the line, blending soft or hard.
  - **chase:** `waves` blocks, each `size` of its share of the line, step along the line once per cycle, in steps of one segment (soft fades between steps).
  - **sparkle:**
    - The base is the first colour at 40 %.
    - Sparks are the last colour at full. `size` is the share of segments sparking at a time.
    - It is deterministic: a hash of (segment, floor(phase × 8)), so it is still a pure function.
  - **breathe:** every segment; brightness between 1 − `size` and 1, sine, in the first colour (the next colour on each new cycle when there are several).
  - **meteor:** a full head of the first colour travels along x once per cycle, with a tail `size` of the line long fading to dark.
  - **fill:** the line fills from x = 0 over the first half cycle and empties over the second, each cycle in the next colour.
  - **yoyo:** a block `size` of the line long, travelling 0 → 1 → 0 once per cycle (triangle), first colour.
- `intensity` scales the result.
- `Engine.ownMotion(): number[]` gives, per segment, the largest one-frame change in visible level that any preset running there would make by itself. It is 0 for static presets. The jump check allows each segment's step ≤ ownMotion + 5 %.
