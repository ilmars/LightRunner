# Timeline: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Timeline page where the programmer adds a recording, lays blocks (colours, levels, effects, looks, Dark, Everything full, Follow the voice) on a layer per group, and presses Start: the sound plays in that browser and Light Runner runs the lights in step with it (or in Prepare, on the stage view only).

**Architecture:** Timelines live in the show (`show.timelines`); recordings in `data/recordings/`. Pure logic (what each group should show at time t, which blocks changed, the clock merge, the loudness track) is in `packages/shared/src/timeline.ts`. A server `TimelineRunner` ticks every 25 ms on the main thread, turns block changes into the existing commands (applied without Undo steps and without stopping itself), and sends Follow-the-voice levels to the worker. The engine gets a fade on `groupLevel` and a smoothed per-group level follow. The page (`web/timeline/`) plays the audio with an `<audio>` element and reports its position over the WebSocket.

**Tech stack:** Node 24 TypeScript (type stripping), zod, node:test, plain JS ESM pages, Web Audio for decoding.

**Spec:** [docs/superpowers/specs/2026-10-25-timeline-design.md](../specs/2026-10-25-timeline-design.md) — read it, including "Decided by the owner" and "Calls made…".

## Global constraints

- Branch `timeline` (main checkout, no worktree). New commits only; never push or tag.
- The engine stays pure (`now` in, DMX out). Clocks, files and sync live in `server/`. Never pass absolute times between threads (the worker's `performance.now()` is not the main thread's).
- Timeline changes go through the same command path as everything else, but **add no Undo steps** and **don't stop the timeline itself**; Stop, Blackout (`blackout`), Basic lights (`safe`) and a song (`look`) from anyone else stop a live timeline.
- One Live timeline at a time; a Prepare timeline runs in that page's own draft and never touches the real lights.
- `npm test`, `npm run typecheck`, `npm run jump-check` pass before every commit; `jump-check` gains timelines (Task 2) and must keep the 5 % rule.
- Design system: dark, nothing bright, 44 px targets, quiet controls, ds- tokens; plain words; works in Safari (iPad) and Chrome/Edge/Safari (laptop).
- Every process an implementer starts (servers, browsers, Electron) is stopped before it reports; `node --check` a script before running it in a browser or Electron; never touch ports 8080/8089 or the owner's installed Light Runner; leave untracked `.claude/launch.json`, `.claude/preview.env`, `tools/worshiptools*.ts` alone.

## Review focus

1. A timeline left running with its page closed: it carries on to its end on the server clock and then stops; nothing stays "running" forever. (Task 3 test.)
2. Two people at once: a Live timeline runs while another tablet is in Prepare, and while a second page opens the same timeline; a second Live Start stops the first. (Task 3 test.)
3. Seeking backwards and forwards repeatedly while playing never steps a light more than the jump check allows. (Task 2 jump check + Task 3 test.)
4. A recording the browser can't decode, or a 0-length file, or one over 100 MB: a plain message, nothing half-saved. (Tasks 4–5.)
5. A block whose colour, effect, look or group was deleted from the show: shown as missing, skipped by the runner, no crash. (Task 1 + Task 3 tests.)

### Task 1: Timelines in the show, and the pure timeline logic

**Files:** Modify `packages/shared/src/schema.ts`, `packages/shared/src/index.ts`, `packages/shared/src/merge.ts`, `server/src/app.ts` (Patch save keeps live `timelines`, as it keeps the controller). Create `packages/shared/src/timeline.ts`. Tests `packages/shared/test/timeline.test.ts`, `packages/shared/test/merge.test.ts`.

**Interfaces — Produces** (in `schema.ts`, exported):
- `TimelineBlock = { id, start: number /* s */, end?: number /* s; missing = until the next block on the layer */, rise: number /* s, 0–600 */, what: BlockWhat }` where `BlockWhat` is one of `{ kind: 'colour', preset: id, level: unit }`, `{ kind: 'level', level: unit }`, `{ kind: 'effect', preset: id, speed?: EffectSpeed }`, `{ kind: 'look', look: id }`, `{ kind: 'dark' }`, `{ kind: 'full' }`, `{ kind: 'follow', low: unit, high: unit, preset?: id }`.
- `TimelineLayer = { group: id | 'stage', blocks: TimelineBlock[] }` (`'stage'` = Whole stage; only `look`, `dark`, `full` there).
- `Recording = { id, name: string, duration: number, loudness: string /* base64, one byte per 1/25 s, 0–255 */, peaks: string /* base64, one byte per waveform bar, ≤ 4000 */ }`.
- `Timeline = { id, name, recording?: Recording, layers: TimelineLayer[], markers: { t: number, text: string }[], offsetMs: number /* −500…500, default 0 */ }`; `Show.timelines: Timeline[]` default `[]`. No `checkReferences` entries (missing refs are skipped, spec call 9).
- `merge.ts`: a `timeline` item kind (added / changed / removed, by id), after `look` in ORDER; removing a group/preset/look leaves timelines alone (the runner skips missing references).

**Interfaces — Produces** (in `timeline.ts`):
- `type GroupTarget = { block: string /* block id */, preset?: id, level?: number, effect?: { preset: id, speed?: EffectSpeed }, follow?: { low: number, high: number }, rise: number, started: number }` and `stateAt(timeline: Timeline, show: Show, t: number): Map<groupId, GroupTarget>` — for every light group, the block in force at t: the most recently started block among the group's own layer and the stage layer (stage `dark` = level 0, keeping the colour; `full` = level 1 with the group's current colour; `look` = that look's entry for the group, colour and level). A block whose `end` passed hands the group back (spec call 3): to the previous block on that layer, else to "no target" (the runner then leaves the group as it was when the timeline started). Missing references → that block is skipped.
- `changesBetween(prev: Map, next: Map): { group, target: GroupTarget | null }[]` (by block id).
- `followAt(recording: Recording, t: number): number` (0–1, linear between the 25 Hz values), `encodeBytes(values: number[]): string` / `decodeBytes(s: string): Uint8Array`, `loudnessTrack(samples: Float32Array, sampleRate: number): number[]` (RMS per 40 ms, normalised to the loud end — 95th percentile = 1, clipped) and `peaksTrack(samples, bars: number): number[]`.
- `mergeClock(serverPos: number, reportedPos: number): { pos: number, jumped: boolean }` — within 0.1 s ease 20 % of the difference; 0.1–0.3 s ease 50 %; beyond 0.3 s jump (`jumped: true`).

- [ ] Tests first: parseShow accepts a show without `timelines` (→ `[]`) and with a full timeline; `stateAt` for a two-layer timeline (stage Dark at 0, front-lights colour at 45 rise 20, stage full at 210) at t = 10, 50, 220; an explicit end hands back; a deleted preset's block is skipped; `changesBetween`; `followAt` interpolation; `loudnessTrack` of a synthetic signal (silence then a tone) gives ~0 then ~1; `mergeClock` cases; merge.ts diff/apply for a timeline; Patch save (`PUT /api/show?source=patch`) keeps the live timelines.
- [ ] Implement; checks; commit "Timelines in the show, and what each group shows at any moment".

### Task 2: Engine — level fades and Follow the voice

**Interfaces — Produces:** `groupLevel {group, value, fade?}` (engine: `group.level.set(value, now, cmd.fade ?? SMOOTH)`); `Engine.setLevelFollow(group: string, value: number | null, now: number): void` — a per-group multiplier on the group's level (null = off, back to 1 over 1 s), smoothed in the engine (rise at most 0.05 per 25 ms frame, fall at most 0.02), not part of `level.target`, Undo or the runtime; `Engine.apply(cmd, now, { quiet?: boolean })` — `quiet` skips the Undo step; worker messages `{ type: 'follow', group, value: number | null }` and `{ type: 'command', cmd, quiet? }`.

### Task 3: The server's timeline runner

**Files:** Create `server/src/timeline.ts`. Modify `server/src/app.ts` (WebSocket messages, stop hook, LiveState), `packages/shared/src/protocol.ts` (`LiveState.timeline`, client messages), `server/src/blind.ts` if drafts need the follow input. Tests `server/test/timeline.test.ts`.

**Interfaces — Produces:**
- Client → server (WebSocket, programmer role): `{ type: 'timelineStart', id, at: number /* s */, prepare?: boolean }`, `{ type: 'timelinePosition', id, pos: number, playing: boolean }`, `{ type: 'timelineStop', id }`. Any role: `{ type: 'timelineStop' }` stops the live one (the operator page's Stop).
- `LiveState.timeline: { id, name, pos, duration, playing } | null` (live only); drafts get theirs in `draftState`.
- `class TimelineRunner { constructor(opts: { show: () => Show, apply: (cmd, opts) => void, follow: (group, value) => void, now: () => number }); start(timeline, at); report(pos, playing); stop(); tick(); get state() }` — ticks every 25 ms; position = merged clock (`mergeClock`) plus `offsetMs`; on each tick computes `stateAt`, sends `changesBetween` as commands (`groupPreset`/`groupEffect` with `fade = rise` when the block starts within this tick, else 1 s; `groupLevel` with fade; stage `look` as `look`, `dark` as level 0 per group with the rise, never a real `blackout`), all `quiet` and marked so the stop hook ignores them; follow values via `follow`; with no position reports it simply runs on its own clock (RF 1); at the timeline's end (its last block's end, or the recording's duration, whichever is later) it stops and clears every follow.
- App: one live runner; a second live Start stops the first; `look`/`safe`/`blackout` from any other source stop it (hook in `run()` before `stageCommand`, ~app.ts:623); Prepare runners per draft session (they apply to that `BlindSession`).

- [ ] Tests (server, with fake clock where possible): start → commands at block times; a page that stops reporting → runs to the end and stops (RF 1); Blackout/Basic lights/a song stop it, its own Dark doesn't; second Start stops the first (RF 2); Prepare runner changes only the draft while a live one runs (RF 2); repeated seeks (RF 3); missing references skipped (RF 5); no Undo steps added; LiveState shows it.
- [ ] Implement; checks; commit "Server: the timeline runner".

### Task 4: Recordings kept on the Mac, played in the browser

The file is kept in the data folder; the browser that presses Start fetches it from there and plays it on its own computer (the Mac never plays sound).

**Files:** Modify `server/src/app.ts` (routes, MIME types, a streamed-to-file upload helper, ranged reads), `server/src/store.ts` if natural. Tests `server/test/recordings.test.ts`.

**Interfaces — Produces** (programmer routes, exact strings in the PIN list): `POST /api/recordings?name=<file name>` (body streamed to `dataDir/recordings/<id>.<ext>`, ≤ 100 MB, ext mp3/m4a/aac/wav by name or type; answers `{ id, name, size }`; over the limit or another type → 413/415 with plain words, partial file removed); `GET /api/recordings/file?id=` (Range requests → 206 with Content-Range; `audio/mpeg`, `audio/mp4`, `audio/aac`, `audio/wav`); `GET /api/recordings` (list); `DELETE /api/recordings?id=` (only when no timeline uses it → else 409).

- [ ] Tests: upload, range read (bytes=0-99 and an open range), too big, wrong type, delete in use. Implement; checks; commit "Recordings: upload and play back from the data folder".
