# APC mini, Companion and OSC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Control Light Runner from an Akai APC mini (USB MIDI), a Stream Deck through Companion (HTTP + polled status), and OSC, with the same actions as the iPad.

**Architecture:** A pure "device actions" layer in `packages/shared/src/devices.ts` turns device-level actions (item N, next, group N level, group N colour K, flash group N, master, …) into ordinary Commands, given the layout and live state; it also works out Next on the server. The server gets HTTP routes and a status JSON for Companion, an OSC UDP listener, and an APC mini driver (pure mapping + LED feedback in `server/src/apc.ts`, MIDI I/O behind a small port interface with `@julusian/midi` as an optional dependency).

**Tech Stack:** Node 24 (type stripping), TypeScript (erasable syntax only), zod, node:test, `node:dgram`, `@julusian/midi` (optional).

**Spec:** [docs/superpowers/specs/2026-10-20-devices-design.md](../specs/2026-10-20-devices-design.md)

## Global Constraints

- Branch `devices` from `main`; main checkout, no worktree; don't push.
- Every input becomes a Command through `App.command()` with role `operator`; the server is the single source of truth; devices always act on the live stage.
- The engine stays pure; timers and sockets live in `server/`.
- `@julusian/midi` is an optional dependency, loaded with a dynamic import; without it or without an APC, Light Runner runs as now and logs one plain line.
- Tests never need hardware (simulated MIDI port, local UDP).
- TypeScript erasable syntax only, `.ts` imports, `import type`. Plain words in Settings and docs.
- `npm test`, `npm run typecheck`, `npm run jump-check` pass before every commit.

## Review Focus

1. A Flash held from the APC or Companion is released when the APC is unplugged, the server restarts the APC driver, or Companion never sends the release (a 15 s safety release for HTTP/OSC flash, like Puff's cap). Pinned in Tasks 1 and 3.
2. Faders never make a light jump (pickup), including after a look change moves the group's level. Pinned in Task 3.
3. Next from a device matches the iPad's Next exactly (Basic lights, lastLook, end of list). Pinned in Task 1.
4. A device action for a group, item or colour that doesn't exist (index too high) is refused quietly (no crash, plain message for HTTP/OSC). Pinned in Tasks 1–2.
5. Malformed OSC packets and HTTP bodies never crash the server. Pinned in Task 2.

### Task 1: Device actions, Next on the server, Companion HTTP

**Files:** Create `packages/shared/src/devices.ts` (export from `packages/shared/src/index.ts`); modify `server/src/app.ts` (routes, flash hold bookkeeping), `server/src/layout.ts` if needed. Tests: `packages/shared/test/devices.test.ts`, `server/test/devices.test.ts`.

**Interfaces — Produces:**
- `export function nextItemId(layout: OperatorLayout-like { runningOrder: {id}[]; basicLights: string | null }, state: { look: string | null; lastLook: string | null }): string | null` — exactly the page's `nextItem()` (web/operator/app.js): the item after the one on stage (Basic lights counts when `look === 'safe'`), else after `lastLook`, else the first non-Basic item; null at the end.
- `export type DeviceAction = { kind: 'item'; n: number } | { kind: 'next' } | { kind: 'backToLook' } | { kind: 'undo' } | { kind: 'basic' } | { kind: 'blackout' } | { kind: 'groupLevel'; group: number; value: number } | { kind: 'groupColour'; group: number; colour: number } | { kind: 'flash'; group: number | 'all'; on: boolean } | { kind: 'master'; value: number } | { kind: 'masterStep'; by: number }` — `n`, `group`, `colour` are 1-based positions: item N in the running order; group N among the layout's **light** groups; colour K in that group's colour list (`presets` without `effect`).
- `export function commandFor(action: DeviceAction, layout, state): Command | { error: string }` — `item` → `safe` for Basic lights else `look`; `next` → the same via `nextItemId` (error "End of the list." at the end); `blackout` → `blackout` (it toggles like the iPad's: while blacked out it brings the lights back — use the same command the page sends); `masterStep` → `master` clamped 0–1; out-of-range positions → `{ error: 'There is no group 7.' }` / `'There is no song 17.'` / `'Group 2 has no colour 9.'`.
- Server: `App.device(action: DeviceAction, source: string): Promise<string | null>` runs `commandFor` and `this.command(cmd, 'operator')`. Flash from a device is held per `source` (like a tablet's flashes) and released when that source goes away (`App.releaseDevice(source)`), and any device flash held longer than 15 s is released automatically.
- HTTP routes (operator, local network), all POST unless noted, answering `{ ok: true }` or 400 with the plain message: `/api/item/:n`, `/api/next`, `/api/back-to-look` (exists), `/api/safe` (exists), `/api/blackout` (exists — check it matches the iPad's toggle behaviour, keep it), `/api/undo` (exists), `/api/group/:n/level/:pct` (exists by id — add positions: a number is a position, otherwise an id), `/api/group/:n/colour/:k`, `/api/flash/:group/on`, `/api/flash/:group/off` (`:group` = position, id, or `all`), `/api/master/:pct` (exists), `/api/master/up`, `/api/master/down` (±10 %). Flash over HTTP uses source `http`.
- `GET /api/companion` → `{ look, lookName, next, nextName, changed, blackout, flashing (bool), master (0–100 int), tempo, groups: [{ n, name, colour, level (0–100 int) }], items: [{ n, name, onStage }] }` — flat and stable for Companion variables.

### Task 2: OSC input

Tests: `server/test/osc.test.ts`.

**Interfaces — Produces:** addresses (case-insensitive prefix `/lightrunner`): `/item n`, `/next`, `/back`, `/undo`, `/basic`, `/blackout`, `/group/<n>/level v` (v 0–1 float, or 0–100 int), `/group/<n>/colour k`, `/flash/<n|all> 1|0` (also `T`/`F`), `/master v`, `/master/up`, `/master/down`. Unknown addresses and bad packets are ignored (logged once per address per minute at most).

### Task 3: APC mini

**Files:** Create `server/src/apc.ts` (pure: model detection from port name; MIDI message → `DeviceAction` or pickup/hold handling; layout + state → LED messages), `server/src/midi.ts` (`interface MidiPorts { list(): string[]; open(name): { send(bytes: number[]): void; onMessage(fn): void; close(): void } }`, the real one via dynamic `import('@julusian/midi')`, and a fake for tests), modify `server/src/app.ts` (start the APC driver: look for a port whose name contains "APC MINI" (case-insensitive) every 2 s; on open, send the full LED state; on state/layout changes, send only changed LEDs; on close, release its flashes with source `apc`; Blackout hold timer 1 s lives here), `package.json` (`@julusian/midi` in `optionalDependencies`), Settings shows "APC mini: connected (mk2)" / "not connected" in the existing status area if there is one (else in the OSC card's neighbourhood). Tests: `server/test/apc.test.ts`.

**Interfaces — mapping (Akai's published protocols; verify against them):**
- **mk2** (port name contains "mk2"): pads notes 0–63 (bottom-left 0, left to right, bottom to top); track buttons notes 100–107; scene buttons notes 112–119 (top to bottom); faders CC 48–56 on channel 1 (48–55 = faders 1–8, 56 = master). Pad LEDs: note-on on channel 1–7 = brightness/behaviour, velocity = palette index; real colours via the mk2 RGB SysEx (`F0 47 7F 4F 24 …`). Button LEDs: note-on, velocity 0 off / 1 on / 2 blink.
- **older APC mini**: pads notes 0–63 (same layout); track buttons notes 64–71; scene buttons notes 82–89; faders CC 48–56. Pad LEDs: velocity 0 off, 1 green, 2 green blink, 3 red, 4 red blink, 5 yellow, 6 yellow blink. Button LEDs: velocity 0/1/2.
- Pads: rows 7–8 (top two) = running order items 1–16 (row 8 left to right, then row 7); rows 1–6 = colours: column c = light group c, row 6 (top of the block) = colour 1 … row 1 = colour 6. Track button c = Flash group c (hold). Scene buttons top to bottom: Next, Back to, Undo, Basic lights, Flash all (hold), Blackout (hold 1 s), spare, spare.
- Feedback: running order pad on stage = bright/green, next = dim/yellow, others = low/off-ish (mk2: item swatch colour at low brightness); colour pads mk2 = the colour's swatch (shown as on the iPad), running one full, others dimmed; older model: running colour green, others yellow, missing ones off; Flash buttons lit while flashing; Blackout button blinks while blacked out; Next lit when there is a next item.
- **Pickup**: per fader, ignore moves until the fader value crosses (or comes within 2 % of) the target's current level; after that it follows until the level changes from elsewhere by more than 2 %, which re-arms pickup.
